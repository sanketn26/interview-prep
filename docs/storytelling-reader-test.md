# Storytelling reader test

Use this protocol before treating structural compliance as improved engagement. Do not tell participants which version is new.

## Sample

- Recruit at least five readers from the intended audience; include both Senior and Staff candidates when possible.
- Test one concept, one design exercise, and one DSA or behavioural page per batch.
- Randomize whether each participant sees version A or B first.
- Preserve snapshots or commit links for both openings.

## Tasks

1. Show only the first screen for 40 seconds.
2. Ask: “Would you continue?” Record yes/no and a one-sentence reason.
3. Hide the page and ask for a one-sentence retell.
4. Ask readers to rate clarity and credibility from 1–5.
5. Reveal the next section and ask what mechanism or decision they expect next.

## Recording template

| Page | Reader cohort | Order | Continue A/B | Retell accurate A/B | Clarity A/B | Credibility A/B | Notes |
|------|---------------|-------|--------------|---------------------|-------------|-----------------|-------|
| | | | | | | | |

Retell accuracy is ✓ only when the reader identifies the system or actor, observable problem, and decision/consequence without using the page's exact wording.

## Decision rule

Continue the rollout when the revised openings improve continuation preference or retell accuracy without lowering median clarity or credibility. Scroll depth may support the result but is not causal by itself. If two consecutive batches fail this rule, pause and revise the contract before adding more scenes.

Never record names, employers, or sensitive interview feedback in this repository. Store only aggregate cohort results.
